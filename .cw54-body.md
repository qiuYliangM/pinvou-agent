## Summary

Threads grow from a single `cwd` into **cwd (primary root) + workspace_roots (full accessible root set)** - the foundation for the single-entry workspace design (project = primary folder + a set of keys). Ported 1:1 from the v0.9.5-line branch `pinvou3/workspace-roots`, rebased onto the current `pinvou3-clean` and carried through seven review rounds (23 commits).

Four layers:
1. **Protocol & session model**: `workspace_roots` on ThreadStart/Resume/Fork params and the Thread DTO (serde-defaulted, legacy payloads decode empty, empty set omitted from frames); SQLite `threads` v5 column; both TUI JSON stores additive.
2. **Turn environment**: runtime root replacement via `Op::SyncSession` / Runtime API with an active-turn fence, effective next turn (snapshot semantics); `normalize_workspace_roots` keeps cwd first and deduped; resume three-state semantics (also fixes the persisted-cwd being overwritten by the current-dir fallback).
3. **Permission sandbox**: materialized at per-turn policy construction; `workspace_write_policy` carries the normalized set; carve-out, `ToolContext::resolve_path`, and execpolicy rule matching all span attached roots - with **Allow-scoped execpolicy rules kept primary-root-only**, so an attached root never widens auto-approval (ask/deny rules may span roots; they only ever add a prompt or a block).
4. **Prompts/instructions**: AGENTS.md discovery stays primary-root-only (test-locked); multi-root sessions gain an `Accessible folders:` line in per-turn turn_meta (capped, absent for single-root). The project_instructions source-label change moved to its own PR: #59.

## Behavior boundary

With no roots configured, **inbound** wire params and legacy persisted records decode exactly as before, and policy values and path decisions are **byte-identical** to single-root behavior. Frames this build **emits** are additive rather than identical: a thread created by this build always carries at least `[cwd]`, so Thread DTO and `Op::SyncSession` frames gain the `workspace_roots` key (legacy decoders tolerate it - exactly what the DTO comment states). No multi-root UI in the TUI; roots enter only via Runtime API/headless. v0.9.12 fork behaviors (SandboxNetworkAccess, repo-boundary instruction walk, restructured compaction) preserved.

## Review remediation (round 2)

All three same-class surfaces flagged in round 2 now carry the root set instead of dropping - and eventually erasing - it:

- `POST /v1/sessions` stamps `detail.thread.workspace_roots` into the saved session metadata.
- `POST /v1/sessions/{id}/resume-thread`: `CreateThreadRequest` gains `workspace_roots` (normalized on create, workspace leading, request-order dedupe) and the resume handler forwards the session's persisted set.
- TUI: the App now carries the session's roots - `LoadSession` seeds it from the persisted metadata, the `AppAction::SyncSession` handler records the action's set (forks inherit the parent's, new sessions reset to empty), `build_engine_config` and every re-sync send forward it, autosave stamps it into the snapshot, and `merge_persisted_lifecycle` restores the persisted set as the disk authority. The TUI still has no multi-root UI; it only stops destroying what other hosts wrote.
- Each surface has a locking regression test, plus one locking the round-1 snapshot-save stamping itself (create normalization, save stamping, resave stability, resume carry-through, merge restore).

## Review remediation (round 3)

Five must-fixes from round 3, all implementation slips in the round-2 carriers or the original port:

- Both TUI fork paths forwarded the root set of freshly constructed metadata (always empty) while claiming forks inherit the parent's set. `fork_from_session` now stamps the source session's set, `fork` stamps the live App set (cached-metadata backfill extended to roots), and the forked sibling inherits the parent's set - all before the save, since the disk-authority lifecycle merge would re-erase any later in-memory correction.
- `switch_workspace` kept the old primary root as an attached writable root after `/cd`; it now applies the same primary-swap semantics as the runtime PATCH branch and `resolve_resume_roots` (old directory leaves, new workspace takes the primary slot, additional roots survive re-normalized).
- `LoadSession` seeded `app.workspace_roots` before the fallible config restore steps; a failed load could push a foreign set into the current session's engine on the next re-sync. Seeding now happens only after every fallible step succeeds.
- `ThreadResumeParams.workspace_roots` became `Option<Vec>` (upstream codex semantics): `None` inherits, `Some([])` explicitly clears back to the bare cwd - previously unrepresentable. `resolve_resume_roots`, parity tests, and a new explicit-clear test follow. `ThreadStartParams` keeps `Vec` (a start has no parent to inherit from); `ThreadForkParams` became `Option<Vec>` in round 7, where a bare fork inherits the parent's set.
- The running-threads resume branch writes the cwd/roots override back to the running-thread cache, so a later parameterless resume cannot fall back to the stale cached set.

Non-blocking round-3 items also landed: `CreateThreadRequest` omits empty roots on the wire; the state layer warns on invalid `workspace_roots` JSON instead of silent degradation; the workspace chip and `/status` summaries use the real root set; a negative execpolicy test pins Allow+relative-path narrowing; a roots-only active-turn fence test; a parsed key-absence assertion for the single-root DTO frame; the v5 migration deliberately does not touch its local `user_version` mirror (terminal step: the stale pre-migration value is never read again); and the commit history was squashed so every commit compiles under `cargo check --workspace --all-targets` (the E0063/E0061 fixups and the born-dead symbol removal are folded into the commits that introduced them).

## Review remediation (round 5)

One durable-loss must-fix and three semantic gaps:

- `/cd` performed the primary swap in memory only, and the autosave merge unconditionally overwrote the stamped live set with the stale disk record - every autosave re-wrote the pre-switch set and the abandoned directory resurrected as a writable root on the next resume. The lifecycle merge now treats disk as authority only against a roots-blind (empty incoming) writer - a non-empty incoming set is a deliberate live-owner mutation and survives; and `switch_workspace` persists the swap immediately with a direct snapshot save (the fork paths' pattern). A session_manager test pins the full switch -> autosave merge -> restart round trip.
- execpolicy scope and path filters matched independently over the root list: a rule scoped to repo R with a relative path could fire on the same path materialized under an unrelated root. The filters are now one gate - a rule's candidate roots are the scoped roots (primary-only for Allow, as before), and rooted path matching runs against those same candidates. A negative + control test pins the pairing with a Deny rule carrying both `workspace` and a relative `path`.
- Worktree subagent children no longer inherit the parent's attached roots (the worktree is the isolation boundary; at base the child could only resolve inside it); explicit `cwd:` swaps are non-isolating and keep the set - disclosed here as the pinned behavior.
- The `Some([])` explicit-clear leg of the resume contract is pinned on the wire (decodes to `Some(vec![])`, re-encodes with the key present), and the non-empty round-trip assert now checks the encoded frame.

Also landed: a disclosure comment on `Runtime::invoke_tool`'s empty root set (app-server lane; attached-root ask and deny rules never fire there, byte-identical to base; scheduled follow-up), and `fork_from_session` stamps the source's root set before the save (round 7 replaced that verbatim stamp with primary-swap semantics).

## Review remediation (round 7)

Three must-fixes and the non-blocking tail, all the same carrier class:

- **M1 — the app-server bridge executed every turn single-root.** `run_bridged_turn` is documented as the only way any app-server surface runs a model, and it runs on a runtime thread created through `POST /v1/threads`; that request carried only model/workspace/mode while `RuntimeThreadHint` persisted only model + cwd. A `thread/start` declaring `workspace_roots` therefore stored the full set on the parent record while every actual turn ran with `[cwd]` - writes under attached roots were denied or prompted even though `thread/read` still reported them. The hint now carries the response thread's roots and `create_runtime_thread` sends them; an empty set stays off the wire, so single-root frames are unchanged.
- **M2 — `/save` dropped the root set, durably.** Freshly built metadata carries an empty set and `/save` wrote it as-is: the managed-dir copy healed only if a later autosave ran, so `/save` then quit was a durable single-root record, and an explicit-path `/save` was never healed at all. The live set is now stamped before the write, the fork paths' pattern. Verified red-green: with the stamp removed the new test fails with `left: []`.
- **M3 — the protocol fork lane inherited the provider but not the roots.** A bare `thread/fork` (the historical shape; the field is new) silently degraded a multi-root parent to `[fallback_cwd]`, and a plain `Vec` gave the wire no way to say "inherit". `ThreadForkParams.workspace_roots` is now `Option<Vec<PathBuf>>` mirroring Resume - absent = inherit, `Some([])` = explicit clear, non-empty = replace - and `Runtime::fork_thread` inherits the parent record it already loads, applying the cwd-only-resume primary swap (the fork's cwd takes the primary slot, the parent's additional roots survive).

Non-blocking items, fixed:

- **N1** `/fork <id>` executed in a different workspace stamped the source's set verbatim while the fork's workspace is the current one, so the disk record violated workspace-is-primary and engine-side normalization re-admitted the abandoned directory as a writable root. It now applies the primary swap `/cd` and the runtime PATCH branch use.
- **N2** `/rename` synced `metadata.workspace` from the live App but not the paired roots, and the pre-first-snapshot rebuild omitted them too; both `/rename` paths now carry the live set. (`/title` mirrors that write path in its own function and was still unstamped - see round 8 M1.)
- **N3** `/resume <export>` re-pointed the session id and messages without resetting `app.workspace_roots`, so the next autosave stamped the previous session's set onto the imported record. The live set is re-derived from the imported metadata.
- **N4** repo law stayed primary-root-only, so a constitution living in an attached root never held writes under that root. `repo_law_plan_decision` now runs once per accessible root in that root's own namespace and keeps the strongest decision (law can only add holds); both call sites (turn loop, ACP admission) pass their root set, and an empty set keeps the single-root behavior exactly. Tests cover an attached root's own block, primary globs not leaking across roots, and a cross-root block outranking an ask.
- **N5** the `Op::SyncSession` apply path switched `app.workspace` before the fallible provider restore but recorded roots only after it, so a failed restore left `workspace: new` paired with the previous session's set. Both are now recorded in the same step, before the fallible work.
- **N6** the state writer degraded `workspace_roots` to `'[]'` silently on serialization failure while the reader warns on malformed JSON, so a non-UTF-8 path lost the set with no visibility. The writer warns through the same channel and keeps the tolerant empty-set fallback.
- **N7** two tests passed without exercising what they named: the exec stamp test asserted nothing about the roots it passed, and the `PUT /v1/sessions` re-save test asserted the value the preceding POST had already written. The stamp test now asserts the persisted set and workspace; the re-save test changes the thread's roots through the runtime PATCH between the calls, so the PUT must write the newer set.
- Disclosed, not fixed: the worktree-subagent root clearing (the child's boundary is its worktree alone) still has no direct test - covering it needs a full worktree spawn harness that does not exist for this path. Recorded as an open test gap rather than claimed as covered.

Body corrections: the phantom "golden frame in the AGENTS.md lock test" and the inverted "v5 migration updates its local `user_version` mirror" claims are gone from the round-3 list; the verification paragraph no longer carries the contradictory macOS sentence; and the four commit messages that cited a nonexistent `WORKSPACE_ROOTS_SYMBOL` constant, a golden frame that landed nowhere, or a `fork_from_session` re-normalization the diff did not make were rewritten (branch rebased; the round-6 tree content is byte-identical to the reviewed one).

## Review remediation (round 8)

One must-fix in a mirror implementation, one must-fix decision resolved by landing the plumbing, and the non-blocking tail:

- **M1 - `/title` was the last disk writer without the roots stamp.** `/rename` and the shared first-snapshot fallback were fixed in round 7, but `/title` carries its own copy of the write path (`title.rs::set_window_title_with_manager`): it loads the record from disk, overwrites `metadata.workspace` from the live App, and saves without the paired set. The exposure is the one the `/rename` comment describes - a `/cd` whose direct save failed leaves the pre-switch set on disk, and `/title` then quit is durable because no turn checkpoint follows to heal it. The main path now stamps `app.workspace_roots` beside `app.workspace`. Test seeds exactly that post-`/cd` mismatch and asserts the persisted pair; verified red-green (removing the stamp fails with the pre-switch set).
- **M2 - ACP `session/load` now carries the persisted root set (option a).** `build_acp_tool_registry` takes the roots and applies them to the `ToolContext` (`with_workspace_roots`) and to the per-turn sandbox policy; `AcpSession` keeps the set so the mode-change rebuild preserves it; `session/load` seeds it from `saved.metadata.workspace_roots`; and the auto-review context reads the registry's set instead of a literal `&[]`. A multi-root session resumed over the IDE bridge therefore keeps the attached-root writes it legitimately held, and an attached root's constitution can hold there. Test: a saved multi-root session loads with the set on the session, in the registry context, and in the materialized writable roots. The body disclosure for this lane is gone, and the `build_direct_workflow_tool` gap keeps its own comment (N5).

- **N2** the AGENTS.md lock test is renamed to what it actually locks (`forkguard_workspace_roots_instruction_discovery_takes_only_the_primary_root`) and its comment now states that the guarantee is the loader's single-root signature - compile-time - not a runtime branch the test could flip.
- **N3** the repo-law doc now matches the pinned behavior: a *relative* target is judged against every root (fail-closed; an extra prompt or block at worst), while execution resolves relative paths against the primary.
- **N4** `Op::SyncSession.workspace_roots` gained a wire-level parity case: an empty set stays off the wire, a non-empty set round-trips, and a legacy payload without the key decodes to an empty set.
- **N5** `build_direct_workflow_tool`'s single-root context now carries the same disclosure comment `Runtime::invoke_tool` has (enforcement-only, byte-identical to base, scheduled follow-up). The ACP side of this item is resolved by M2.
- **N6** `normalize_workspace_roots`'s doc records the lexical-dedup boundary: symlink dual spellings both survive normalisation, and the callers that enumerate writable roots canonicalize per root for exactly that reason.

## Known scope boundaries (non-blocking, follow-ups)

- ACP/MCP headless registry contexts still build their `ToolContext` without roots, so `context.workspace_roots` reads stay empty there; populating them needs the load_session roots plumbing. Until then the ACP host answers the carve-out question conservatively (`&[]`) while ask-rule checks and repo law read the (empty) registry context, so that lane keeps exactly its previous single-root behavior - unify when the wiring lands.
- Round 7 makes the protocol fork lane inherit explicitly: `Runtime::fork_thread` reads the parent record it already loads and inherits its set when the request carries none (`Option<Vec>`, absent = inherit, `Some([])` = clear), so a bare `thread/fork` no longer degrades to the fallback cwd. Remaining fork-adjacent gaps: `Event::SessionUpdated` carries no roots (exec's `latest_workspace`/`latest_workspace_roots` pair can diverge if a mid-run SyncSession ever appears - today exec only syncs at startup), and subagent calls with an explicit `cwd:` keep the parent's root set (undocumented, to pin).
- The headless workflow-tool context (`build_direct_workflow_tool`) passes empty roots: enforcement, not display - it silently denies attached-root writes to a session that legitimately holds them. Scheduled follow-up targets enforcement.
- Scheduled follow-ups from review: canonicalize once at `normalize_workspace_roots` intake (lexical dedup lets `/var/x` + `/private/var/x` both survive), align the "additional roots" doc wording with the full-set storage convention (`Op::SyncSession` doc, `app.workspace_roots` doc, `core/session.rs` comment), and add red-green tests for the remaining TUI seeding/stamp paths (picker, startup resume, the CLI fork, `/cd` swap) - `/save` gained one in round 7.

- Corrections to earlier disclosures, per review: the active-turn fence already covers roots changes (only a roots-scoped test case was missing - now added), and the execpolicy lexical-normalization gap exists identically for single-root cwd in base - this PR widens the exposure surface without introducing the flaw.
